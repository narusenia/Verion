# 引き継ぎ: M5 の残りを Mac で

Windows 機（RTX 3080）での M5 の Vulkan は終わり、`mise run check`・`mise run shaders:check`・`mise run test:gpu`（21 件）が通っている。状態の正本は `docs/implementation/M5-restir-incremental/README.md`。Windows 側の前の引き継ぎは `2026-11-06-m5-windows.md`。ここから先は Metal が要るので Mac で行う。

## 分かったこと: ReSTIR を使わなくても Megakernel が遅くなっていた
- Vulkan で `mise run bench` が基準より `cube` +22〜25%、`scale` +10〜14% になった。5 回測っても同じで、揺れではない。基準を取ったコミット（`c8545f5`）を別 worktree で回すと基準どおり（cube −0.5%）で、ReSTIR を入れた最初の Vulkan コミット（`2b5b8a2`）から +24% だった。ガラスの修正や差分更新は関係しない
- 原因は、`pt_core.slang` の ReSTIR のコードが、無効（`params[36] == 0`）でもカーネルのレジスタを使うこと、と見ている
- 直し方は特殊化定数（コミット `068847e`）: `pt_core.slang` の `restirCompiled`。`false` で ReSTIR をコンパイル時に消す。Vulkan は ReSTIR の有無ごとにパイプラインを持ち（`renderer.rs` の `pathtrace`・`wavefront`）、使うほうだけ遅延で作る。結果は cube +1.7〜3.2%、scale +1.4〜1.7%
- Mac の引き継ぎ時に出ていた「cube が +15〜28% で揺れた」は、同じ原因だった可能性が高い

## 1. Metal に `restirCompiled` を渡す（これが本題）
- 既定値は `true`（今までと同じ動き）にしてあるので、何もしなくても壊れないが、Mac の退行は残る
- 生成された MSL は `constant bool fc_restirCompiled_0 [[function_constant(0)]]` を持ち、値が渡されないと `true` になる。対象は `pathtrace`・`wf_select`・`wf_extend`・`wf_shade` の 4 本（`git show 068847e --stat` の `.metal`）
- `crates/verion-gpu-metal/src/renderer.rs` で、パイプラインを作るときに `MTLFunctionConstantValues` に bool を index 0 で渡す。値は `restir.is_some()`。Vulkan と同じく、ReSTIR の有無ごとに 2 つ持ち、使うほうだけ遅延で作る（`git show 068847e -- crates/verion-gpu-vulkan/src` が見本）
- 蓄積の途中で ReSTIR の設定が変わるとエラー、は今のまま。パイプラインの切り替えが起きるのは設定を変えた次の蓄積から

## 2. 確認の手順
1. `git pull` して `mise run check`、`mise run shaders:check`（MSL はバイト比較。Windows で生成した `.metal` が一致するはず。違えば `mise run shaders` で作り直してコミット）
2. 上の 1 を入れたあと、`mise run bench` を複数回。Mac の既存の基準（`apple-*.json`（その Mac の機種のもの））に対して `cube` が 10% 以内に戻ること。戻らなければ、特殊化定数が Metal のコンパイラで効いていない（`restirCompiled` が使われている箇所が 2 つだけかも含めて見る）
3. 画像一致（REQ-GPU-007）を ReSTIR 有効で見る（M5 の手順 5。Windows では Metal がないので未実施）。Beauty の `exr_diff` のチャンネル平均 0.1% は求めない（ReSTIR の再利用は乱数の流れに敏感なので、高 spp の平均で比べる）:
   - 両方の機で `cargo run --release -p verion-render-cli -- scenes/many_lights.gltf -o DIR/many_lights.exr --width 512 --height 384 --spp 4096 --mode interactive`（Windows 機では `--backend vulkan`）。`scenes/cornell_box.gltf` も同じ
   - `sh scripts/backend_diff.sh REFERENCE_DIR TEST_DIR`。ReSTIR 有効の閾値は、結果を見て決める（ガラスのシミのテストの値は Cornell Box で GI のブロック平均の最大差 0.18、赤青のバランス 0.08）
   - ReSTIR を切った（`--mode reference`）画像が、今までと同じ閾値で一致すること
4. 終わったら M5 の README の項目 4・8 と完了条件の最後を「済」にする。Windows 側の結果は、Vulkan の GPU テスト 21 件通過、`eval_restir.sh` の測定（ADR-0016 に追記済み）、bench の退行解消
