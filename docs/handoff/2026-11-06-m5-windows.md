# 引き継ぎ: M5 の Vulkan を Windows 機（RTX 3080）で

M5 の Metal 側と共通部分は Mac で終わり、計画書は `docs/implementation/M5-restir-incremental/README.md`（状態の正本）。Vulkan のクレートは Mac でビルドできないため、`crates/verion-gpu-vulkan/src/renderer.rs` に最小の対応（trait の新しいメソッド、バインディング 19 と 20〜25、Reservoir のバッファ、`update` は `UpdatePlan` に従う差分更新）を書いた。Mac では lib.rs の cfg と Cargo.toml のターゲット指定を一時的に外して `cargo check` と `clippy -D warnings` を通した（ash は macOS でも型検査できる）。実機のビルドと実行は未確認なので、最初に `cargo build -p verion-gpu-vulkan` と実機テストで確かめる。

## 1. コンパイルを通す（書いてある対応の確認）
- `RayTracingBackend::update(&mut self, &Scene, &Changes) -> Result<UpdateReport, Error>`
- `RayTracingBackend::set_restir(Option<Restir>)`
- `Accumulation::restir_bytes() -> usize`
- 共有型は `verion-gpu` の `Restir`・`UpdateReport`・`RESTIR_FLOATS_PER_PIXEL`（80）。`pack::base_params` の引数に `restir` が増え、`PARAM_WORDS` は 39

## 2. ReSTIR（`shaders/include/pt_core.slang` は共通。SPIR-V は再生成してコミット済み）
- 新しいバインディング 19 `restir`（`RWStructuredBuffer<float>`）。Wavefront のバインディングは 19〜24 から 20〜25 に動いた。descriptor は SPIR-V の反射から作るので、バッファを足して割り当てるだけのはず
- `restir` は 1 画素 80 float（2 フレーム分と作業領域）。ReSTIR が無効なら Metal の `no_lighting` と同じ小さなダミーを割り当てる。有効なら `accumulate` の最初に作ってゼロ埋めする（ゼロが「近傍として使えない」の印）。メモリは Metal の実装（`Accumulation::restir`）を参照
- ReSTIR が有効なら Megakernel は 1 Dispatch 1 サンプル（他の画素の前フレームを読むため。Metal は `encode_megakernel` で `params[35]` を 1 にしている）
- Dispatch の間のバリアは、Wavefront では Dispatch ごとの全体メモリバリアが既にあるので足りるはず。Megakernel も Dispatch の間に同じバリアが要る
- 蓄積の途中で ReSTIR の設定が変わったらエラー（Metal と同じ文言）
- パラメータブロックが 39 語になったので、dynamic offset の間隔（アラインメント）を確かめる

## 3. 差分更新 `update`（実装済み。実機で確かめる）
`crates/verion-gpu-vulkan/src/renderer.rs` の `update` は Metal の `Renderer::update`（`crates/verion-gpu-metal/src/renderer.rs`）と同じ計画（`pack::UpdatePlan`）に従って書いてある。descriptor は `accumulate` ごとに作るので、バッファの差し替えだけで済む。BLAS は自分の三角形のコピーを持つため、位置バッファを新しくしても触っていないメッシュの BLAS は有効なまま、という前提で書いた（実機で要確認）。形状の追加は表と BLAS を全部作り直し、パイプラインは使い回す。以下が計画の内容:
- 材質: `pack_materials(scene, false)` で表だけ詰め、画像の並び（`images`）が変わったときだけ `pack_materials(scene, true)` でテクスチャ表を作り直す。Emitter と Instance 表も作り直す
- ライト: `pack_lights`、環境マップは `env_key` が変わったときだけ `pack_env`
- Transform: Instance 表と TLAS と Emitter
- 変形（`changes.deformed`）: そのメッシュの頂点・UV・法線を表の範囲に書き換え（`MeshRange`）、その BLAS だけ作り直し、TLAS を作り直す
- 形状の追加（`plan.full`）: 全部作り直すが、パイプラインは使い回す。設定（積分器・ReSTIR・Adaptive など）は引き継ぐ
- 返す `UpdateReport` は、作り直した BLAS 数、TLAS を作り直したか、書いたバイト数
- テスト: Metal の `tests/update.rs`・`tests/restir.rs` を移植して `crates/verion-gpu-vulkan/tests/update.rs`・`tests/restir.rs`（`--ignored`、型検査済み、未実行）に置いた。`mise run test:gpu` で走る。落ちたときは、コードとテストのどちらが間違っているかを実機で切り分ける

## 4. 確認の手順
1. `mise run check`（Windows の CI と同じ）、`mise run shaders:check`、`mise run test:gpu`
2. `cargo run --release -p verion-render-cli -- scenes/many_lights.gltf -o out.exr --mode interactive --spp 32` が動くこと（`--backend vulkan`）
3. `sh scripts/eval_restir.sh` を RTX 3080 で。結果を `docs/adr/0016-restir-di-gi-interactive-mode.md` の測定の表に並べて足す（Metal との比較）
4. `mise run bench`。ReSTIR の変更で既存の基準（`nvidia-geforce-rtx-3080-ac.json`）を 10% 以上悪くしていないこと
5. Metal と Vulkan の画像一致（REQ-GPU-007）を ReSTIR 有効でも見る。Beauty は `exr_diff` のチャンネル平均 0.1% は求めない（ReSTIR の再利用は乱数の流れに敏感なので、高 spp の平均で比べる）
6. 終わったら M5 の README の項目 4・8 と完了条件の最後を「済」にする
