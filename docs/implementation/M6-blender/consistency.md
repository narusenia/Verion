# DCC 間の一貫性と Cycles との比較（項目 14）

測定日 2026-11-06。Blender 5.2.3 LTS（4.5.15 LTS も同じ傾向）、Metal。`scripts/blender_test.sh` で再現できる。

## Blender 経由と glTF 経由（合否の基準）

`plugins/blender/tests/test_consistency.py`。同じシーン（床・拡散球・金属球・Sun・Point）を、アドオンで描いた画像と、Blender の glTF エクスポータが書いた幾何・材質・カメラに KHR_lights_punctual（アドオンと同じ換算）を足して `render-cli` で描いた画像とで比べる。

| 指標 | 結果 | 閾値 |
|---|---|---|
| 平均の比 | 1.0000 | 0.97〜1.03 |
| 4×4 ブロックの相関 | 1.00000 | 0.995 超 |
| ブロックの最大差（最大値に対する割合） | 0.0001 | — |

同じ乱数列で描くため、変換が同じなら画素まで一致する。ずれたら、アドオンの変換かインポータのどちらかが変わっている。

## Metal と Vulkan の画像一致（項目 16、REQ-GPU-007）

`test_consistency.py` のシーン（128×96、96 spp）を Mac（Metal、Blender 5.2.3 LTS）と Windows（RTX 3080、Vulkan。Blender 5.2.3 LTS と 4.5 LTS で 5 回実行）で描き、`verion.read_image` で読んで比べた。Blender 経由（`blender.exr`）と glTF 経由（`cli.exr`）の両方。

| 画像 | Vulkan / Metal の平均の比 | ブロック相関 | 最大の画素差 | 画素差の平均 |
|---|---|---|---|---|
| Blender 経由 | 1.0000 | 1.00000 | 0.0007 | 約 1e-7 |
| glTF 経由 | 1.0000 | 1.00000 | 0.0010 | 約 1e-7 |

5 回の Windows 実行のすべてで同じ。目安（平均の比 0.99〜1.01、ブロック相関 0.999 以上）を大きく上回る。画素までは一致しない（約 4 分の 1 の画素がビット単位で同一）。浮動小数の丸めの差の範囲。

## Cycles との比較（参考値）

どれも「Verion ÷ Cycles」。Cycles に合わせることは目標ではなく、変換の誤りを見つけるための値（許容は各テストの閾値）。

| 項目 | 平均の比 | ブロック相関 | メモ |
|---|---|---|---|
| ライト（Point・Spot・Sun・Area 3 形状） | 0.972〜0.974 | — | 床の拡散で測定。換算は `light-units.md` |
| IES（下向きの絞り） | 0.965 | 0.9996 | 1 cd を 0.0707 倍（光の強さに対して）として合わせた |

| ライトリンク（面光源） | Verion 0.466 / 0.018、Cycles 0.455 / 0.021 | — | 〃 |
| 拡散・粗い誘電体 | 0.858 | 0.9886 | |
| 光沢のある誘電体 | 0.888 | 0.9892 | |
| 粗い金属 | 0.899 | 0.9971 | |

材質の平均が Cycles より 10〜15% 暗い。以前の測定では、同じ入力の BSDF そのものの差が垂直入射で約 2.7%、かすめ角で約 9%（Cycles の Principled は誘電体の拡散と鏡面を Fresnel で重ね、多重散乱を足す）あり、画像の平均はそれより大きく出ている。内訳（BSDF 差と、床からの反射光の差など）は分けて測っていない。変換の誤りなら Blender 経由と glTF 経由の比較（上）でも出るはずで、そちらは一致している。Octane との比較は M6 の後（REQ-ACC-002）。
